# 第五章代码块标记修复 — 手机端阅读宽度异常

## 日期
2026-07-27

## 修改摘要
修复第五章（ch_5）Markdown 中 ` ``` ` 标记数量为奇数（9个）导致的渲染异常。多余的 ` ``` ` 使正则表达式将整个登山叙事段落（54行/980字符）错误纳入 `<pre><code>` 代码块，在手机窄屏下因 `<pre>` 不换行而产生水平滚动条，视觉上"更宽"。

## 涉及文件
- `data/chapters/ch_5.json` — 修改 content 字段，在代码块2的关闭 ` ``` ` 与场景标题代码块之间插入独立空代码块分隔

## 根因分析
1. ch_5 的 content 中有 9 个 ` ``` ` 标记（奇数）
2. 第4个标记（位置1022）同时承担"代码块2的关闭"和"场景标题代码块的开启"双重角色
3. 第5个标记（位置1036）因此成为"多余开启符"，正则 `[\s\S]*?` 向下贪婪匹配至第6个标记（位置2020），吞掉中间980字符的登山叙事
4. 被错误包裹的文本在 `<pre><code>` 中不换行，手机窄屏下出现水平滚动条

## 修复方式
在代码块2的关闭 ` ``` ` 后插入一个空代码块分隔（`\n\n\`\`\`\n`），使两者独立：
- 原：`\n\`\`\`\n周五，增城白水寨。\n\`\`\``
- 改：`\n\`\`\`\n\n\`\`\`\n周五，增城白水寨。\n\`\`\``

修复后 ` ``` ` 数变为 10（偶数），正则正确匹配 5 个代码块，登山叙事恢复为普通段落。

## 关键决策
只修改数据文件内容，不修改渲染器代码。因为 Markdown 标准要求 ` ``` ` 必须成对出现，渲染器行为正确。

## 注意事项
- 未来新增/编辑章节时需确保 ` ``` ` 标记成对使用
- 其他章节（ch_1~ch_10）的 ` ``` ` 数量均为偶数，无此问题
- 场景标题推荐改为 `---` 分隔线或 `###` 标题，更符合 Markdown 语义
