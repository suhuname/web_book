## Instructions

### 项目简介

本项目是都市言情小说 **《星落之城》** 的创作项目。小说以上海梅雨季为背景，讲述了设计师林晚与星澜文化创始人顾深之间关于相遇、重逢与成长的故事。

## 核心创作流程

### Phase 0: 记忆加载

每次创作前，必须先加载记忆以了解当前进度：

1. 读取 `.roo/skills/write-book-content/memory/INDEX.md`，浏览写作进度索引
2. 根据当前任务类型，按需读取具体记忆文件：
   - **章节创作** → 读取最新的写作进度记忆 + 大纲
   - **续写** → 读取前一章的记忆 + 大纲
   - **修改** → 读取相关章节的创作记忆
3. **必须** 读取 [`data/outline.md`](data/outline.md) 获取章节大纲指引

### Phase 1: 需求分析

- 明确创作目标（写新章节 / 扩写 / 修改 / 润色）
- 确认目标章节在大纲中的定位（第几幕、什么剧情节点）
- 检查该章节是否已有内容，已有内容的字数统计
- 参照大纲确认本章的核心剧情点

### Phase 2: 内容创作

**创作规范：**

1. **字数要求**：每章中文字数不少于 **2000 字**
2. **风格统一**：
   - 第三人称有限视角（以林晚视角为主，适当穿插顾深视角）
   - 现代都市文学风格，细腻但不拖沓
   - 注重环境描写与环境氛围烘托（上海的梅雨、城市光影）
   - 对话自然，符合人物性格
   - 适度使用 Markdown 格式：`**加粗**` 强调重点，`---` 场景分隔（渲染为 `<hr>` 水平线），**禁止**使用 ` ``` `（会被渲染为代码块而非场景分隔）
3. **结构规范**：
   - 开篇要有场景设定（时间/地点/氛围）
   - 发展要有冲突或情感推进
   - 高潮要有情绪爆发点或关键转折
   - 收尾自然收束，剧情推进到该停的地方即停
4. **章节结尾规范** ⚠️ 重点注意：
   - **禁止**在每章结尾刻意添加总结性、收尾性、点题性的语句（例如概括本章主旨、抒发感悟、"而这一切，才刚刚开始"式的感慨、为全章做总结的段落）
   - 章节内容写完即**直接停止**，不需要任何形式的"收束语"或"落幕句"来给本章画句号
   - 若剧情本身自然需要以某个动作、对话或场景画面收尾，可以用该画面结尾，但不得额外附加旁白式的总结或抒情
   - 后续章节直接接着写即可，章节之间的衔接靠剧情本身，不靠结尾的总结句
5. **人物一致性**：
   - 林晚：细腻内敛、坚韧执着、设计师身份
   - 顾深：外表冷峻内心温柔、沉稳克制、创业者的决断力
   - 苏漫：开朗直率、闺蜜角色、情感助攻
   - 沈瑶：前期冷淡有敌意、后期成为朋友
   - 周明：忠诚能干的助理、暗中助攻
   - 程昱：竞争对手、制造外部冲突
   - 顾母：佛山人，独撑家业的要强母亲；**不是阻力，是助攻**——最怕儿子一直一个人，对他带回女朋友高兴得隔天就订了来广州的位子，对林晚先是好奇、很快真心接纳（全书不写婆媳对抗）

### Phase 3: 字数验证

创作完成后，必须验证字数：

```bash
node -e "const fs=require('fs');fs.readdirSync('data/chapters').filter(f=>f.endsWith('.json')).sort((a,b)=>parseInt(a.match(/\d+/))-parseInt(b.match(/\d+/))).forEach(f=>{const c=JSON.parse(fs.readFileSync('data/chapters/'+f,'utf8'));const n=(c.content||'').match(/[\u4e00-\u9fff\u3400-\u4dbf\uf900-\ufaff]/g)||[];console.log(c.title+': '+n.length+'字'+(n.length>=2000?' ✅':' ❌ 不足2000字'))})"
```

### Phase 4: 数据同步

1. 更新 [`data/novel.json`](data/novel.json) 中的章节内容
2. 同步更新 [`data/novel.js`](data/novel.js) 保持与 novel.json 一致
3. 更新章节的 `title`（如从"第四章"改为"第四章 并肩作战"）
4. 更新 `summary` 字段为本章剧情摘要

### Phase 5: 版本备份

每次章节内容最终定稿后，必须执行版本备份：

1. 运行备份脚本将当前章节文件保存到 [`temp/`](temp/) 目录：
   ```bash
   node tools/backup-chapter.js data/chapters/<章节ID>.json "<描述>"
   ```
   示例：
   ```bash
   node tools/backup-chapter.js data/chapters/ch_2.json "闺蜜夜话-v2"
   ```

2. 备份文件命名格式：`YYYYMMDD_HHmmss_章节ID_描述.json`

3. 自动管理上限 **100 个备份**，超出时删除最旧的文件

4. 需要恢复历史版本时，从 `temp/` 目录找到对应备份文件，手动复制回 `data/chapters/` 目录

### Phase 6: 记忆记录

创作完成后，必须记录本次创作操作：

1. 在 `.roo/skills/write-book-content/memory/` 下创建新的记忆文件，命名格式：`YYYY-MM-DD-序号-简短描述.md`
2. 记忆文件包含：
   - **标题**: 本次创作的简短标题
   - **日期**: 创作完成日期
   - **章节**: 创作的章节 ID 和标题
   - **字数统计**: 创作前后的字数对比
   - **剧情摘要**: 本章的核心剧情要点
   - **关键决策**: 创作中做出的剧情调整或重要决定
   - **下一章铺垫**: 为后续章节埋下的伏笔或线索
   - **注意事项**: 后续创作需要注意的事项（人物关系变化、时间线等）
3. 更新 `.roo/skills/write-book-content/memory/INDEX.md`，在索引表中追加新条目

## 写作风格指南

### 语言风格

- **叙述**：温和细腻的中文文学语言，避免过分华丽或过分口语化
- **对话**：自然生动，符合人物身份和性格
- **描写**：善用感官细节（视觉、听觉、触觉、嗅觉），营造沉浸感
- **节奏**：张弛有度，紧张场景用短句，抒情场景用长句
- **对话＋白描**（核心写法）：对话前后必须补动作／神态／停顿／环境／心理，**不要写"你一句我一句"的干对白**；范本见第一章，细则见下方「对话白描规范」

### 对话格式规范 ⚠️ 重点注意

对话格式是本项目**最核心的风格要求**，必须严格遵守：

1. **对话使用双引号 `""`** — 所有人物对话、自言自语、内心独白均使用 `""`（双引号），**禁止**使用 `「」`（角括号）
2. **对话单独成行** — 对话原则上单独起一行，每行以 `"` 开头和结尾。如果对话后需要接动作或神态描写，可以接在同一行，示例：
   ```text
   "都到齐了？开始吧。"

   他在主位坐下，目光扫过一圈，在林晚脸上停了一秒，微微点了点头，然后移开了。

   "先给大家介绍一下。"他抬手指向林晚，"林晚，新来的设计师，从今天起正式加入团队。她在盛远传媒做了三年，作品很有想法。"
   ```
3. **作品/概念标题使用 `「」`** — 作品名称、概念标题（如 `「星落之城」`、`「界限」`）保留 `「」` 格式，与对话区分
4. **引用的短语使用 `""`** — 叙述中引用的短语、内心想法也用 `""`，而非 `「」`
5. **格式对比**：
   | 场景 | 正确格式 | 错误格式 |
   |------|---------|---------|
   | 对话 | `"还没走？"` | `「还没走？」` |
   | 作品标题 | `「星落之城」` | `"星落之城"` |
   | 引用短语 | `"理解"` | `「理解」` |
   | 叙述中引用 | `"改了十版最后用第一版"` | `「改了十版最后用第一版」` |
6. **对话归属必须写具体名字，禁止「他说／她说」** ⚠️ — 对话前后的提示语一律写**人物姓名**（"顾深说""林晚问""顾母说""周明说"），**不得写"他说""她说""他问""她问"**。人多时读者不该为了弄清"这句是谁说的"而回头数行。
   - 同一段连续对话可只给一次提示语，但**每换一个人说话都要能一眼看出说话人**；靠上下文难以辨认时（短句问答、"嗯。""我知道。"这类），直接补名字
   - 对照：
     | 场景 | 正确格式 | 错误格式 |
     |------|---------|---------|
     | 两人对话 | `"明天再看。"顾深说，"今天先睡。"` | `"明天再看。"他说，"今天先睡。"` |
     | 三人同场 | `"瘦了。"顾母说。` | `"瘦了。"她说。` |
     | 短句问答 | `"为什么。"顾深问。` | `"为什么。"`（无归属，靠猜） |

### 对话白描规范 ⚠️ 重点注意（对话必须"带描写"）

> **范本**：第一章《雨夜邂逅》。**已落地**：ch_15《星光下的约会》、ch_16《同频》、ch_17《雨里的粥》、ch_18《这次换我》、ch_20《他很少提起的家人》、ch_21《她很高兴》、ch_22《第一次见面》、ch_23《坚定选择》、ch_24《她给的答案》、ch_25《暮色之约》、ch_26《解约》、ch_28《从零开始》、ch_29《一顿夜宵》、ch_32《夜里的那盏灯》、ch_34《还有一张》（2026-10-07／2026-10-08 按此写法重写）。

本项目的对话不是"你一句我一句"的剧本式对白，而是**对话＋白描**——每一处对话（尤其是关键对话、情绪转折处）都要在其前或其后补上具体描写，让读者"看见"说话的人，而不是只读到台词。**此后所有新章节一律按此写法创作；修改旧章节时也按此标准补足。**

写法要点（"四补"）：

1. **补动作** — 说话前后给一个具体的小动作（推、按、转、停、放、捏、点、敲）。例：`他把那沓样张合上，用手掌按住，推到桌子另一头。`／`她伸手，把他面前那支停在桌沿的铅笔，往中间推了推。`
2. **补神态** — 写眼神、嘴角、停顿、呼吸、脸色的变化。例：`顾深笑了一下。那笑很浅，可他没藏，她看见了。`
3. **补停顿** — 关键句前用"他停了一下""她顿了一下，像是在挑一个不那么扎人的说法"制造留白与分量；沉默要写成动作或环境，不能空转。
4. **补环境／感官** — 每场戏先给场景锚点，对话中穿插声音、光线、温度、气味。例：`水龙头开得很小，水流细细地冲在杯壁上`／`楼下有人关门，砰的一声，很闷`／`一道光从天花板上扫过去，很快就没了`。

其他要求：

- **句子放长、节奏放缓**：叙述用完整句，把"谁、怎么做的、什么感觉"一并写出；**不要连续多行干巴巴的短对白**。紧张场景可在长句中夹短句。
- **心理／潜台词**：重要台词之后，补一句人物此刻的内心或没被说出口的东西（例：`他说这句话的时候，眼睛没有看她，看的是桌上那半张草图。`）。
- **对话归属仍写具体姓名**（见上一条第 6 点）——白描**不能替代**归属，两者要同时满足。
- **不喧宾夺主**：白描服务于情绪与信息，一场戏内同类型描写不要重复堆砌。

技法对照：

| 项目 | ✅ 推荐（对话＋白描） | ❌ 避免（干对白） |
|------|----------------------|------------------|
| 关键问句 | `"那你为什么不过去。"林晚问。`<br>`顾深的手在膝盖上放了一下。`<br>`"那天我穿一件起球的毛衣。"顾深说，"袖口还有一点墨。"` | `"那你为什么不过去。"`<br>`"那天我穿一件起球的毛衣，袖口还有一点墨。"` |
| 情绪转折 | 先给停顿与环境，再出那句最重的话 | 直接连抛多句对白，无铺垫 |
| 短句问答 | 每句补一个动作或神态，使说话人一眼可辨 | 一串"嗯。""我知道。""好的。"无描写、无归属 |

> 自查口径：通读一场对话，若把引号里的台词全删掉，剩下的叙述是否还能让人"看见"这两个人在做什么、什么状态——若不能，就是白描不足。

| 语法 | 用途 |

## 章节插入工具（insert-chapter.js）

当需要在已排好序的章节之间**插入新章节**时（例如在第七章和第八章之间插入过渡章），使用此工具自动处理所有数据同步，避免手动重编号出错。

### 用法

```bash
node tools/insert-chapter.js <插入位置ID> <新章节标题> [内容文件路径]
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `<插入位置ID>` | 在哪个章节**之后**插入 | `ch_7` |
| `<新章节标题>` | 新章节的完整标题 | `"第八章 心墙渐融"` |
| `[内容文件]` | 可选，包含正文的文本文件 | `./temp/ch8-content.txt` |

### 完整流程示例

```bash
# 1. 将新章节正文写入临时文件（也可以用 echo 直接传）
echo "章节正文内容..." > ./temp/new-chapter.txt

# 2. 运行插入脚本
node tools/insert-chapter.js ch_7 "第八章 心墙渐融" ./temp/new-chapter.txt

# 3. 清理临时文件（可选）
rm ./temp/new-chapter.txt

# 4. 重启服务器使变更生效
# （在另一个终端中执行）
# python server.py
```

### 脚本自动完成的事项

1. ✅ 在 `novel.json` 的指定位置插入新章节
2. ✅ 后续章节的 `id` 和 `title` 自动递增重编号（ch_5→ch_6→ch_7…）
3. ✅ 重命名 `data/chapters/` 下对应的 JSON 文件（**逆序处理**，防止级联覆盖）
4. ✅ 更新每个 JSON 文件内部的 `id` 和 `title` 字段
5. ✅ 重新生成 `data/novel.js`
6. ✅ 自动更新 `data/outline.md` — 插入新章节行、重编号后续章节标题、更新幕范围

### 不包含自动处理的内容（需要手动完成）

### ⚠️ 故障恢复指南

当插入脚本执行异常（如文件丢失、级联覆盖）时，按以下优先级恢复：

**第一优先级：Git 恢复（推荐）**
```bash
# 1. 查看最近的提交中受影响的文件
git show --name-status HEAD

# 2. 从 Git 恢复单个章节文件
git show HEAD:data/chapters/ch_X.json > data/chapters/ch_Y.json

# 3. 用 Node.js 脚本批量恢复并重编号（参考 temp/restore-chapters.js 示例）
```

**第二优先级：版本备份恢复**
从 `temp/` 目录找到对应备份文件（`YYYYMMDD_HHmmss_章节ID_描述.json`），手动复制回 `data/chapters/`

**第三优先级：手动重建**
根据 `data/novel.json` 中的 summary 和大纲指引重新创作丢失的章节内容

> **原则**：优先使用 Git 恢复，Git 不可行时再考虑备份或重建。每次操作前先提交 Git 以便快速回滚。

## 约束

1. **先出大纲，确认后再写** — 任何新增章节、修改剧情、调整大纲的操作，**必须先设计大纲方案并展示给用户确认**，得到明确同意后方可进入正文创作。禁止直接创作未经确认的内容
2. **必须参考大纲** — 每次创作前必须读取 [`data/outline.md`](data/outline.md)，严格按照大纲剧情走向写作
3. **字数控制** — 每章不少于 2000 中文字数，创作后必须验证
4. **人物一致性** — 不得偏离已建立的人物性格和关系
5. **数据同步** — 修改 novel.json 后必须同步更新 novel.js；新增/插入章节优先使用 [`tools/insert-chapter.js`](tools/insert-chapter.js) 自动完成重编号和数据同步
6. **记忆记录** — 每次创作后必须在 memory/ 中记录并更新 INDEX.md
7. **向后兼容** — 不破坏已存在的章节数据格式
8. **创作连续性** — 注意章节之间的衔接，保持时间线和剧情的连贯性
9. **结尾不写总结句，但要留悬念（钩子）** — 每章结尾**禁止**刻意添加总结性/收尾性/点题性语句（概括主旨、抒发感悟、"而这一切才刚刚开始"式感慨、为全章做总结的段落）；**但鼓励以"钩子"收尾**：一个未接的电话、一条没打开的消息、一个反常的举动、一个未解的问题、一个即将到来的人，用具体信息或画面留白，让下一章可以直接从这一点接着写。

   > 区分标准：**钩子 = 新信息/新悬念（引向下一章）；总结句 = 对本章的回顾与抒情（让剧情停住）。**
   > 示例（ch_19 结尾）：走出咖啡厅，顾深手机响了，屏幕上只有一个字"妈"，他按灭屏幕、反扣回口袋，说了句"没什么"——她第一次发现，认识他两个多月，她唯独不知道他家里有谁。
10. **对话必须"带描写"（对话＋白描）** ⚠️ — 每一处对话前后都要补上动作／神态／停顿／环境／心理，**禁止"你一句我一句"的干对白**；句子放长、节奏放缓，白描不得替代对话归属（归属仍写具体姓名）。详见「写作风格指南 · 对话白描规范」，**范本：第一章《雨夜邂逅》**，**已落地：ch_15《星光下的约会》、ch_16《同频》、ch_17《雨里的粥》、ch_18《这次换我》、ch_20《他很少提起的家人》、ch_21《她很高兴》、ch_22《第一次见面》、ch_23《坚定选择》、ch_24《她给的答案》、ch_25《暮色之约》、ch_26《解约》、ch_28《从零开始》、ch_29《一顿夜宵》、ch_32《夜里的那盏灯》、ch_34《还有一张》**。此后所有新章节一律按此写法创作
